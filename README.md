# ReturnLens

## EdgeOne Pages

迁移仓库 `dongdongdad666-art/ReturnLens`，分支 `codex/edgeone-migration`。使用 `npm run build:edgeone`，输出 `dist`，无需环境变量或COS。详见 [部署说明](docs/EDGEONE.md)。保留当前线上业务版本，未加入后续宣传片功能。

ReturnLens 是一个用于演示服饰电商退货决策闭环的 React MVP：从订单、退货、评价和客服聊天 CSV 中找出按 SKU 聚合的问题，展示脱敏证据与估算损失，支持人工复核、整改草案、动作看板和实验复盘。

> 独立概念项目。内置品牌、CSV、AI 摘要、整改草案、趋势和实验数据都是模拟内容；没有真实客户、真实模型调用或已验证的商业成果。

## 本地运行

需要 Node.js（建议使用项目锁定依赖所兼容的当前 LTS 版本）。在项目根目录执行：

```bash
npm install
node scripts/generate-demo-data.mjs
npm run dev
```

打开终端显示的本地地址，然后从 `/import` 点击“使用内置模拟品牌”。生成脚本会创建 `public/demo/` 下的四份可重复的演示 CSV。

验证：

```bash
npm test
npm run build
```

也可执行 `npm run lint` 检查代码风格。

## 六个核心界面

- `/import`：CSV 导入、映射、数据质量、脱敏提示与模拟预算控制。
- `/`：经营总览与按可挽回损失排序的优先队列。
- `/issues`：问题中心、筛选和部分结果覆盖提示。
- `/issues/:issueId`：问题详情、脱敏证据、置信度、人工复核和整改草案入口；演示 SKU 为 `/issues/I-SKU-123`。
- `/actions`：整改动作看板。
- `/experiments`：固定模拟实验复盘。

完整访谈演示逐秒脚本见 [docs/DEMO_SCRIPT.md](docs/DEMO_SCRIPT.md)，设计与证据边界见 [docs/CASE_STUDY.md](docs/CASE_STUDY.md)。

## 数据与隐私边界

- CSV 在浏览器内读取；订单和退货是分析的必需输入，评价和客服聊天为可选证据。
- 导入时会对常见中文姓名、手机号和地址模式做本地正则脱敏；这只是 MVP 启发式规则，不是完整的隐私合规或数据泄露防护方案。
- 当前 MVP 不向外部模型服务发送数据。原始 CSV 与原始证据文本不写入 `localStorage`；刷新后，证据摘录不可恢复，需要重新导入。
- 浏览器会保存派生的问题、批次/预算状态和脱敏后的整改摘要，方便演示断点恢复。整改草稿及历史的所有文本在保存与读取时均经过脱敏；明显的对话原文会移除，负责人只可选择团队。请勿在共享设备或真实敏感数据场景中把此演示级本地存储当作安全数据仓库。
- 每次点击“开始模拟分析”替换分析数据时，会清除全部旧整改动作及版本历史，包括相同 SKU；尚未完成关联批次的问题不会进入经营总览、详情或整改流程。
- 如需回到首次运行状态，在“数据与设置”点击“清除本地演示数据”。它会清除全部 ReturnLens 本地存储、当前导入文件和会话证据，并返回空导入页；其他应用的数据不受影响。网站数据设置清理可作为无法打开应用时的备选方式。

## 真实、确定性逻辑与模拟输出

| 本地真实且可重复的逻辑 | 模拟/概念输出 |
| --- | --- |
| CSV 解析，字段和数值校验，字段映射建议及高风险映射确认 | 内置模拟品牌与演示 CSV |
| 常见姓名、手机号、地址模式的正则脱敏 | “AI 智能匹配”文案、AI 摘要与整改草案 |
| 按 SKU 聚合，关键词归因，直接损失、置信度和 15%–35% 可挽回损失区间 | 草案的重写文本、模型超时按钮和模型价格所代表的真实调用 |
| 本地 Token 成本估算、预算预检、批次/部分结果和整改状态机 | 总览趋势与实验卡的有效/无显著变化/证据不足结论 |

置信度表示规则所见证据的充分程度，按基础 45%、每笔退货 +5%、每条证据 +3%（证据贡献最高 +20%）、总分最高 95% 计算；它不表示因果确定性。可挽回损失仅按置信度与改善率假设计算，用于排序，非审计财务结果。

## 生产化方向

要用于真实业务，需要新增：

- 受控模型 API，带 prompt/响应记录、成本账本、脱敏和人工复核策略；
- 身份认证、组织隔离、角色/权限与审计日志；
- 加密存储、保留/删除策略和经安全评估的数据处理；
- 后端批处理、队列、重试、幂等、可恢复任务与真实预算执行；
- 经授权的订单、售后、客服、商品、实验和工单平台集成；
- 基于真实财务口径的损失验证、标注数据归因评估，以及预先定义的实验设计。

这些是后续工作，不是当前 MVP 的已实现能力。
