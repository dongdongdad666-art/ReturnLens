# ReturnLens 6 分钟演示脚本

> 演示前置清理（必做）：执行 `node scripts/generate-demo-data.mjs` 后启动本地应用；在“数据与设置”点击“清除本地演示数据”，确认回到空导入页，再点击“经营总览”开始本脚本。此操作清除本地派生状态、动作历史及会话证据。使用桌面浏览器。内置品牌、AI 摘要、草案和实验数据均为模拟内容。不要把屏幕上的金额或实验状态说成真实业务成果。

## 00:00–00:35  服务对象、问题、商业价值和概念声明

- 路线：`/`（首次运行会显示空的经营总览）。
- 点击：左侧“数据与设置”。
- 说：“ReturnLens 面向需要决定先改哪个 SKU 的服饰电商运营。它把退货、证据和整改动作放进一条复核链；这是独立概念项目，下面的品牌、数据和 AI 输出都是模拟的。”
- 可见结果：进入 `/import`，标题为“导入经营数据”，并显示“演示数据已在本地完成脱敏，MVP 不会发送至外部模型服务”。

## 00:35–01:20  导入模拟数据、字段映射、本地脱敏、Token 预算

- 路线：`/import`。
- 点击：右上“使用内置模拟品牌”。
- 说：“我加载内置模拟品牌的四类 CSV。页面按列名给出订单编号和商品编码的映射及置信度；它会在浏览器内校验，并在进入分析前对退货原因、评价和聊天文本做本地脱敏。”
- 可见结果：订单、退货、评价、客服聊天卡片显示行数和“内置模拟品牌”来源；数据质量区域更新，开始按钮可用。

- 点击：“开始模拟分析”。
- 说：“这里立即完成的是本地确定性归因和金额计算。下面的 Token 价格、批次和预算面板只模拟模型调用成本，MVP 不会调用真实模型。”
- 可见结果：显示“模拟生成：已完成本地脱敏与确定性分析”，以及“分析进度与预算”面板、每百万 Token 价格输入、默认 ¥0.60 预算上限和“开始批次模拟”。

- 点击：“开始批次模拟”，再点击“处理下一批”两次，停在 60 / 81 条、¥0.48 / ¥0.60。
- 说：“新分析会清空旧整改动作和版本历史。只有全部关联记录处理完的问题才能复核；现在前两批已完成 SKU-123 的关联记录，可以进入总览。”

## 01:20–02:15  经营总览与最高优先级问题

- 路线：点击左侧“经营总览”，到 `/`。
- 点击：“查看最高优先级问题”。
- 说：“总览按可挽回损失的估算区间排列，而不是把它当成审计后的财务数字。这里优先展示待复核、已确认或已修正的问题，帮助运营先看证据更充分、潜在损失更高的 SKU。”
- 可见结果：总览显示“可避免损失”的区间、“高优先级问题”和“分析覆盖率”；点击后进入最高优先级问题详情。标题通常是 `SKU-123 尺码相关退货异常`，但应以页面实际排序为准。

## 02:15–03:15  证据详情、置信度和人工确认

- 路线：当前 `/issues/:issueId`；如需固定入口，在问题中心点击 `SKU-123 尺码相关退货异常`，即 `/issues/I-SKU-123`。
- 浏览/指向：滚动到并指向“脱敏证据摘录”区域；随后点击“确认问题”。
- 说：“这页把损失区间、确定性关键词规则和脱敏文本并列展示。置信度是证据充分度：基础 45%，每笔退货加 5%，每条文本证据加 3%，但文本证据最多贡献 20 分，总分最高 95%；它不是因果概率。模拟建议有明确标签，最后决定权在人工。”
- 可见结果：可见“规则匹配”“置信度说明”“模拟生成”和脱敏证据；点击后状态提示“已确认”，并启用“生成整改方案”。

## 03:15–04:25  草案生成、驳回、重写和进入整改看板

- 路线：停留在 `/issues/I-SKU-123`（或当前已确认问题的详情页）。
- 点击：“生成整改方案”；等待“生成中”消失。
- 说：“这不是模型回答，而是标记为‘模拟生成’的确定性草案。它可以被业务人员编辑，不能绕过负责人、截止日期和目标指标。”
- 可见结果：抽屉显示 V1、整改触点、具体内容、负责人、截止日期、目标指标和版本历史。

- 点击：“驳回并重写”；在“修改要求”输入 `补充 M/L 码实测边界，并把目标指标写成可验证口径。`；点击“按意见重新生成”。
- 说：“我把具体约束留在驳回记录里，再生成 V2；这让建议可追溯，而不是把首个输出直接发布。”
- 可见结果：等待后出现版本 2，版本历史记录 V1 的驳回原因，V2 文本包含反馈。

- 点击并填写：“负责人”选择 `商品运营` 团队，“截止日期”选一个未来日期，“目标指标”填 `M/L 码相关退货率下降 15%`；点击“确认并入看板”。不填写个人姓名，不粘贴客服原文。
- 说：“只有补全执行责任和验证指标后，动作才进入看板。”
- 可见结果：跳转 `/actions`，提示“整改动作已加入看板”，新动作聚焦在“待执行”列。

## 04:25–05:15  预算暂停、部分结果和断点恢复

- 路线：点击左侧“数据与设置”，到 `/import`。
- 点击：从保存的 60 / 81 条进度继续，点击“处理下一批”一次。不要点击“开始模拟分析”，后者会替换数据并清空已演示的整改动作。
- 说：“前两批在默认预算内完成。下一批会在执行前检查预算，超过上限时暂停，而不是悄悄超支。”
- 可见结果：状态变为“预算已暂停”，并显示下一批预计费用超过已授权上限；已处理数量、已花费预算和任务状态仍可见。

- 点击：浏览器刷新；然后在恢复的 `/import` 页面点击“结束分析并查看部分结果”，再在确认区点击“确认结束并查看部分结果”。
- 说：“刷新后，浏览器只恢复派生任务状态、问题和动作，不恢复原始 CSV 或原始证据文本。现在我保留已完成批次，并让剩余记录保持待分析。”
- 可见结果：刷新后预算暂停与进度仍在；确认后进入 `/issues?coverage=…`，显示分析覆盖率横幅、“已完成的问题”和“待分析记录”。覆盖百分比随内置数据版本而定。

## 05:15–06:00  实验复盘、技术边界和下一步

- 路线：点击左侧“实验复盘”，到 `/experiments`。
- 点击：依次指向“有效”“无显著变化”“证据不足”三张卡片，无需触发操作。
- 说：“这三张卡演示复盘口径：有效、无显著变化和证据不足都要能被看见。它们是固定本地样本，不代表真实实验结论。当前 MVP 的真实部分是本地 CSV 校验、脱敏、规则归因、金额/置信度公式、预算预检与状态机；AI 文本、趋势和实验结果都是模拟。下一步才是接入授权数据、模型 API、权限、后端任务和真实实验治理。”
- 可见结果：三张卡均带“模拟实验数据”，并分别展示有效、无显著变化、证据不足，以及覆盖率和观察期字段。
